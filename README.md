# ドルとリラ

USD/TRY（ドルリラ）のポジション、スワップ、為替差損、証拠金リスクを記録・可視化する静的Webアプリです。GitHub Pages上で動作し、ポジション・決済・元本履歴などのユーザーデータはブラウザの `localStorage` に保存します。

公開版: https://protchan.github.io/Doller-to-Lira/

## 主な機能

- USD/TRYポジションの追加・編集・決済・削除
- ポジション単体のFX損益・累積Swap・Net損益グラフ
- 配信された日次USD/TRY ASK・USD/JPY・TRY/JPY・Swapの閲覧
- ヒロセLION FXのUSD/TRY Swap履歴を参照したSwap会計
- 配信USD/TRY ASK 23時足終値とUSD/JPYを日次評価レートとして使用
- 日中最大ASKを使ったショート側のストレス・証拠金リスク確認
- 累積Swap / 保有lot / 為替差損益 / 総損益の可視化
- 月次PnLカレンダー
- ロスカットライン・証拠金維持率の推移
- 元本変更履歴を考慮した維持率 / LC計算
- JSONバックアップ / 復元、CSVエクスポート
- スマホと1366×768程度のノートPC向けレスポンシブ表示

## 日次データの方針

公開版の「日次データ」は **配信サービスの閲覧画面** です。一般ユーザーが日次レートやSwapを入力・編集・削除する機能はありません。

配信対象日に対しては、次の値を配信データから決定します。

- USD/TRY: 配信されたASK 23:00終値
- USD/JPY: 配信された23:00参照値
- TRY/JPY: `USD/JPY ÷ USD/TRY` の合成値
- Swap: 公開済みのヒロセUSD/TRY Swapデータを会計ルールに従って反映

従来版で保存されていた「手入力レート」「手入力Swap」「日次TRY/JPY手入力」などは、配信データが存在する日については配信値に置き換えます。配信範囲外にある古い日次履歴は削除せず、閲覧専用の旧履歴として保持します。

設定画面からも、日次レート入力方式、Swap入力方式、デフォルトSwap、日次TRY/JPY入力、参照データ再構築などの公開設定は撤去しています。元本、1 lot通貨数、レバレッジ、ロスカット閾値など、ユーザー固有の運用設定は引き続き変更できます。

## 現行の計算前提

初期値は **1 lot = 1,000通貨**、レバレッジ25倍、ロスカット閾値100%です。これらは設定画面から変更できます。

USD/TRYのFX損益はTRY建ての値動きをJPYへ換算します。通常の日次評価では、配信USD/JPY ÷ 配信USD/TRYから合成したTRY/JPYを使います。

決済済みポジションについては、決済入力時に実口座の円換算TRY/JPYを保存でき、その実測値を最終FX損益の円換算に使用します。これは日次データの配信レートとは別の、ポジション固有の決済情報です。

必要証拠金は、`data/hirose-usdtry-margin.json` に登録済みの日付では **ヒロセLION FXが公表したUSD/TRYの1Lot（1,000通貨）あたり公式必要証拠金**をそのまま使用します。公式値をまだ登録していない将来日についてのみ、前営業日のUSD/JPY参照値から `USD/JPY × 1,000 × 4%` を100円単位で切り上げて推定します。将来日の公式値は自動昇格させず、ユーザーから更新指示があった時点で公式発表値をデータへ追加し、その日を「推定」から「公式」へ切り替えます。画面上も必要証拠金を「公式 / 推定」で区別します。ロスカットラインは設定した維持率閾値を基準に推定する管理用の値です。

## Swapの表示・会計上の計上日

ヒロセのSwap表にある **元データ日 D の金額を、次の営業日 C に表示し、会計上も C に計上**します。金曜などの元データは土日を飛ばして次の営業日に計上します。

このずらし方は、日次チャート上で **為替差損益が動く営業日と、Swapが計上される営業日を同じ横軸上で比較しやすくする**ための管理上のルールです。元のヒロセSwap金額そのものは変更せず、計上日だけを次の営業日へ移します。

ポジションごとのSwap権利判定も、この移動後の計上日 C を基準にします。

```text
建玉日 < Swap計上日 <= 決済日
```

つまり次の扱いです。

- **Swap計上日に新規建てしたポジションには、その日のSwapを付与しない**
- **Swap計上日に決済するポジションには、その日のSwapを付与する**
- 3日分・4日分などの複数日Swapは分割せず、元データの総額を次の営業日にまとめて計上する
- 土日はSwap計上日とせず、画面上のSwapは0円扱いにする

## 配信・参照データ

公開版が直接使用する主なJSONは次の3系統です。

- `data/hirose-ask-close-23.json`: USD/TRY ASK 23時足終値とUSD/JPY
- `data/hirose-ask-day-high.json`: 日中最大ASK
- `data/hirose-usdtry-swap.json`: ヒロセUSD/TRY Swap履歴
- `data/hirose-usdtry-margin.json`: ヒロセUSD/TRYの過去公式必要証拠金と、公式値へ切り替える日付

ブラウザ側に同期された日次スナップショットは計算・チャート表示用のキャッシュとして保持されますが、配信対象日の値は配信JSONが正であり、一般ユーザーから編集することはできません。

日中最大ASKはリスク表示にも使用し、日次終値とは別に「日中にどこまで不利なASKへ動いたか」を確認するための参照系列として扱います。

## 実行時アーキテクチャ

Productionでは `scripts/runtime-manifest.mjs` を唯一の実行順定義として、18個の役割別sourceをビルド時に1本の `app.bundle.js` へ結合します。ブラウザ上でpatchファイルを動的fetchしたり `eval` したりはしません。

主要な責務は次のように分離しています。

- `patch-hirose-core-20260913.js`: ヒロセSwap・翌営業日計上・必要証拠金
- `patch-backend-core-20260913.js`: 派生損益の唯一の計算キャッシュ
- `patch-position-edit-fast-lc-20260913.js`: ポジション編集とLC探索
- `patch-ask-day-high-20260913.js`: 日中最大ASKのread-only参照
- `patch-readonly-daily-service-20260912.js`: 配信値同期と閲覧専用UIポリシー

以前の手入力Swap、手入力レート選択、日次TRY/JPY入力、参照データ再構築、同日Swap会計、二重derived cacheなどの互換レイヤーはProduction manifestから外しています。旧ファイル自体は移行履歴・ロールバック材料としてリポジトリに残しますが、公開bundleには入りません。

## データ保存

ポジション、決済情報、設定、元本履歴などのユーザーデータはブラウザの既存 `localStorage` キー `dollar-to-lira:v1` を継続利用します。構造整理のためにユーザーデータを初期化・移行し直す必要はありません。

日次データも表示・計算用スナップショットとして同期されますが、その公開値は配信データが正です。ブラウザデータ削除や端末移行に備え、「バックアップ」からJSONを保存できます。

## CI / デプロイ

`.github/workflows/pages.yml` で、JavaScript検査、fixture policy、配信スクリプトテスト、production bundle構成検査、runtime smoke test、Playwright E2Eを実行します。

ブラウザE2Eは重複を避けるため階層化しています。ローカルChromiumで全回帰を実行し、ローカルWebKitではブラウザ依存の操作・PWA・表示系を確認します。Pagesデプロイ後は、ホスティング・キャッシュ・ネットワーク統合に重要なsmoke/regressionだけをChromium/WebKitで再確認します。純粋な会計不変条件を同一buildに対して4回繰り返す構成にはしていません。

主な回帰検証対象は、配信専用の日次データ、旧手動モードから配信モードへの移行、Swap翌営業日計上、建玉日除外・決済日包含、複数日Swap、決済時円換算、ポジション編集、元本履歴、日中最大ASK、維持率・LC、累積グラフ、カレンダー、スマホ/PCレイアウトです。

> 本サービスは記録・可視化を目的とする管理ツールです。証拠金・ロスカット計算は設定値に基づく概算で、実際の判定は利用中のFX業者の取引ルールが優先されます。投資助言ではありません。
